What the app does

Sprint Canvas adds a Capacity page to Jira projects (Project page module). It uses a selected Scrum board to compute demand vs capacity for the next 3 sprints and shows:

  • demand vs capacity (in Story Points or Hours/Days, depending on board estimation)
  • utilization %
  • health for the next 3 sprints (OK / Overbooked / No signal)
  • data quality signals (unestimated / unassigned)

Known limitations

  • Scrum boards only (Kanban boards are not supported).
  • The app focuses on the next 3 sprints (active + future).
  • Best signal requires:
    • issues estimated, and
    • issues assigned to people (for assignee-based capacity scaling / overrides)

Troubleshooting

1) Health shows “No signal”

Common causes:

  • Sprint has no issues
  • Issues exist but are unestimated / unassigned
  • Board estimation is not configured

What to do:

  • Add estimates to remaining issues
  • Assign issues to people
  • Ensure the board uses a numeric estimation field (Story Points or time)

2) Utilization is missing / blank

Utilization relies on:

  • detected estimation field (Story Points or time)
  • a non-empty sprint issue set
  • configured capacity

What to do:

  • Confirm sprint issues have estimates
  • Confirm capacity is configured in Settings

3) I changed scopes and now the app errors

If app scopes changed, Jira may require a re-consent / upgrade cycle.

What to do:

  • forge deploy -e production
  • forge install --upgrade -e production -p Jira -s <your-site>.atlassian.net

Data & privacy

The app does not send Jira data to external services. It stores only project configuration (board id + capacity settings + optional overrides) in Forge Storage.

Privacy policy: /products/sprint-canvas/privacy-policy/

Reporting bugs / feature requests

Include:

  • project key
  • board id (if known)
  • steps to reproduce + screenshots
