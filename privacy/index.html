Privacy Policy

Effective date: 2026-02-14

Monolyn Labs builds privacy-first iOS apps and lightweight Atlassian Cloud tools. We aim to collect as little data as possible, and we do not use third‑party trackers or ad tech.

1. Website (monolyn.nl)

This website is a static site hosted on Cloudflare Pages. We do not run analytics scripts, advertising pixels, or third‑party tracking.

  • No cookies for analytics are set by this site.
  • Server logs: like most hosting providers, Cloudflare may process basic request logs (e.g., IP address, user agent) for security and delivery.

2. Support email

If you email support@monolyn.nl, we receive the contents of your message and any attachments. Our support inbox uses standard email providers (e.g., Gmail) to receive mail.

  • Use this only for support requests. Do not send sensitive personal data.
  • We retain support emails only as long as needed to resolve the request and for basic record‑keeping.

3. iOS apps

Our iOS apps are designed for local storage and typically keep data on your device. We do not require an account to use the core functionality.

  • No third‑party tracking SDKs are intentionally integrated.
  • Local data: any content you create in the app stays on your device unless you export/share it.
  • Crash diagnostics: Apple may provide crash reports depending on your device settings. If such reports are available to us, they are used only to improve stability.

4. Atlassian Cloud apps

Our Atlassian Cloud apps for Jira run inside your Atlassian Cloud environment (e.g., via Atlassian Forge). These apps only access data necessary to provide the feature, and data handling is subject to Atlassian’s platform controls.

Sprint Canvas (Jira)

Sprint Canvas provides a capacity planning view inside Jira projects. It may access Jira data needed to compute demand vs capacity, utilization, and health signals.

Data we access (from your Jira site)

  • Project identifiers (project key / id) — to load and store project-level configuration.
  • Boards (Scrum) + board configuration — to detect estimation configuration (Story Points vs time / custom field).
  • Sprints (active and future) — to show the next 3 sprints.
  • Issues in sprints — to read fields needed for calculations, including:
    • estimation field value (Story Points or time field)
    • assignee (accountId and display name)

Data we store

We store configuration in Atlassian Forge Storage, scoped to the Jira site + project, such as:

  • selected Scrum board id (and board name)
  • default weekly capacity per person
  • optional per-person capacity overrides (keyed by assignee accountId)

Data we do not store

  • We do not persist issue descriptions, comments, attachments, or other issue content.
  • We do not sell your data.

Sharing and external services

As designed, Sprint Canvas does not send Jira data to external services (it runs on Atlassian Forge). Data transmission occurs over Atlassian infrastructure. Configuration is stored using Atlassian-provided storage.

Data retention

Configuration is retained while the app remains installed, unless removed or overwritten by users. To request deletion of stored configuration, contact us at support@monolyn.nl.

5. Changes

If we materially change this policy (for example, by adding analytics), we will update this page and adjust the effective date.

6. Contact

Privacy questions: privacy@monolyn.nl.
